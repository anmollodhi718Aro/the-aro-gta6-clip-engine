# Measured Clip Candidate Pack

The analysis CLI produces UTC chat timestamps. They must not be treated as video offsets directly.

Once the operator has a local recording they are authorized to process and has measured the UTC timestamp corresponding to media offset zero, create a review pack:

```bash
python -m backend.app.clip_pack youtube_clip_plan.json \
  --media-origin-utc "2026-11-19T12:00:00+00:00" \
  --output-dir clip_pack
```

Replace the example timestamp with the measured origin for that exact recording. Do not guess it from the livestream start time or a displayed clock. If the offset has not been measured, stop before mapping.

The command writes:

- `clip_candidates.csv`: sortable edit notes with media-relative start/end seconds.
- `clip_candidates.md`: compact human review sheet.

Candidates that start before the recording, end before it, or exceed the local renderer's 180-second limit are marked not renderable. No video is downloaded, rendered, uploaded, or published by this command. The CSV is not an approval to publish. Review source consent, context, and game/music/third-party rights before editing or distribution.


## Multi-anchor clock calibration

Instead of one media-origin timestamp, you can supply at least three independently measured synchronization anchors from the same source:

```bash
python -m backend.app.clip_pack youtube_clip_plan.json \
  --clock-anchors-json examples/clock_anchors.example.json \
  --output-dir clip_pack
```

The JSON must contain `anchors` entries with `source_id`, timezone-aware `chat_time`, and measured `media_seconds`. Optional `max_residual_seconds` and `max_drift_ppm` define fit tolerances. CLI flags `--max-anchor-residual` and `--max-clock-drift-ppm` override them. The fit rejects poor residual/drift and refuses extrapolation outside the measured interval. A clock report generated by THE ARO Studio contains reusable anchors and can be passed directly to this option. See [Clock Sync](CLOCK_SYNC.md).

## Candidate review-score alignment checks

The optional quality score awards recording-alignment points only when the row
is marked renderable, its start/end bounds are valid, the measured
`end_seconds - start_seconds` agrees with `duration_seconds` within 50 ms,
and both the declared duration and measured bounds remain within the
180-second review limit. Boolean values are rejected as numeric metadata.
The score is a data-completeness aid for human review, not a prediction of
views or permission to publish.
